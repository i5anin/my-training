# Формат сообщений бота (Bot API 10.2)

Документ фиксирует, как собираются сообщения телеграм-бота gym777 и почему
выбраны именно эти блоки. Целевая версия — **Bot API 10.2** (14.07.2026),
библиотека — grammY 1.45.1.

## Порядок блоков карточки упражнения

Сверху вниз, как отдаётся в `sendRichMessage`:

| № | Блок | Содержимое |
|---|---|---|
| 1 | `heading` (size 3) | значок и название упражнения |
| 2 | `paragraph` | «План на 14.08, пт · заметка тренировки» |
| 3 | `photo` или `video` | демонстрация упражнения, подпись — название |
| 4 | `heading` + `list` | **Подходы**: «1 · 45 кг × 8», «2 · 50 кг × 8» … |
| 5 | `paragraph` | схема, темп, отдых |
| 6 | `heading` + `list` | Настройка снаряда |
| 7 | `heading` + `list` | Исходное положение |
| 8 | `heading` + `list` | Выполнение по шагам |
| 9 | `paragraph` ×3 | Дыхание · Ощущение · Разминка |
| 10 | `heading` + `list` | Ошибки |
| 11 | `paragraph` ×2 | Верный вес · Прогрессия |
| 12 | `blockquote` | замечание по спине |
| 13 | `footer` | «gym777» и дельта под спойлером |

Размер типичной карточки — около 4000 символов при лимите 32768.

## Медиа упражнения

Файлы лежат в `data/photos`. Порядок поиска в `WorkoutMediaService.forExercise`:

1. `ex-<exerciseId>.jpg|jpeg|png|avif|webp|mp4|mov|webm` — персональный
   снимок или видео упражнения;
2. картинка целевой группы мышц (`грудь.jpg`, `плечи.jpg`, `ноги.jpg`,
   `пресс.avif`, при появлении — `руки.jpg`, `спина.jpg`).

Видео уходит блоком `video`, изображение — блоком `photo`. Локальный файл
передаётся объектом `InputFile` прямо внутри блока: grammY рекурсивно
находит его в `rich_message.blocks[N]` и подменяет на `attach://<id>`,
отправляя тело multipart. Путь через `file_id` тоже работает и не требует
multipart, но для локальных файлов не нужен.

## Что проверено на живом боте

| Возможность | Статус |
|---|---|
| `sendRichMessage` с `blocks` | работает |
| `InputFile` внутри блока `photo` | работает |
| `file_id` внутри блока `photo` | работает |
| `editMessageText` с `rich_message` | работает, правит сообщение на месте |
| `InlineKeyboardButton.style` (`primary`/`success`/`danger`) | принимается API |
| `RichTextSpoiler` | работает |
| `has_spoiler` у фото | работает |
| Кастомные эмодзи (`custom_emoji`) | **не проходят**: API отвечает `ok: true`, но сущность не сохраняется |

Кастомные эмодзи проверены четырьмя наборами (`Topics`, `AdaptiveStatus`,
`tgmacicons`, `AIActions`) и тремя способами разметки (HTML `tg-emoji`,
ручные `entities`, `RichTextCustomEmoji`). Ни одна комбинация не сработала;
у аккаунта-владельца `is_premium: false`. Идентификаторы сохранены в
`TELEGRAM_EMOJI_MAP`, код подставит их автоматически, когда ограничение
снимется.

## Блоки, которые нельзя использовать

Клиент владельца (Telegram Desktop) не отображает часть блоков 10.2:

| Блок | Что видит пользователь | Замена |
|---|---|---|
| `table` | строку-заглушку «Таблица» | нумерованный `list` |
| `details` | только заголовок, содержимое скрыто | плоский `heading` + `list` |
| `has_checkbox` у элементов списка | пункт без текста | обычный список |
| `date_time` | значение поля `text` как есть | в `text` пишется «14.08, пт» |
| `credit` у `blockquote` | отдельная строка под цитатой | жирный префикс внутри цитаты |

Поэтому в карточках эти блоки не применяются, хотя API их принимает.
При обновлении клиента ограничение можно снять — код собран так, что
достаточно вернуть соответствующие ветки в `TechniqueRichBuilder`.

## Правка вместо повторной отправки

Идентификаторы отправленных сообщений хранятся в БД:

- `digest_log` — сводки, ключ `date + workoutId` (0 — служебное сообщение
  «за день записей нет»);
- `card_log` — карточки техники и шпаргалка, ключ `workoutId + exerciseId`
  (`__sheet__` — шпаргалка).

Повторный вызов правит прежнее сообщение: `editMessageText` с
`rich_message` для блочных, `editMessageCaption` для фото с HTML-подписью.
Ошибка «message is not modified» гасится, «message to edit not found»
приводит к удалению записи и отправке нового сообщения.

## Ограничения API, которые учитываются в коде

- текст сообщения — 4096 символов, подпись к фото — 1024, rich — 32768;
- `sendMediaGroup` — от 2 до 10 элементов;
- `callback_data` — до 64 байт (отсюда короткие префиксы `d:p:`, `d:w`);
- таблица — до 20 колонок, в ячейке только инлайн-разметка;
- в кнопке-ссылке допустим только публичный `http(s)` адрес: `localhost`
  и приватные диапазоны отклоняются с «Wrong HTTP URL».
